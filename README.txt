Vocal Flow｜GitHub Pages 歌曲資料版
=================================

一、部署到 GitHub Pages
1. 將 vocal-flow-local 資料夾內的全部檔案放到 GitHub repository 根目錄。
2. GitHub repository → Settings → Pages。
3. Build and deployment 選擇 Deploy from a branch。
4. 選擇 main branch 與 /(root)，儲存後等待網址產生。
5. 請用 GitHub Pages 的 HTTPS 網址開啟；麥克風不能在一般 HTTP 網頁使用。

本版本不需要 server.py、啟動網站.bat、Node.js 或 Python。

二、支援裝置
- Windows：Chrome、Edge、Firefox。
- Android：Chrome 等支援 getUserMedia 的瀏覽器。
- iPhone / iPad：Safari；必須使用 HTTPS，並在按下開始後允許麥克風。
- 瀏覽器的「麥克風」網站權限若曾被封鎖，請到網站設定重新允許。
- 建議戴耳機，避免鋼琴示範被麥克風收進去。

三、Level 3 抽題規則
1. 先從已載入的歌曲 JSON 中等機率抽一首歌。
2. 可組合篩選段落、歌手、演唱類型、指定歌曲、BPM、整句音域與歌詞字數；畫面會即時顯示符合的歌曲與句子數。
3. 「只要副歌」只抽明確標示 type=chorus 的句子。特定歌手或演唱類型被選取時，缺少相應欄位的歌曲視為不符合；選「全部」時才納入未標示資料。
4. 音域條件要求整句最低音與最高音都落在設定範圍內；休止符不計入音域。
5. 可搜尋並指定單一歌曲，也可搜尋歌手後複選；按「套用並換一題」或一般「換一題」即依目前條件抽題。
6. 畫面會顯示歌曲名稱、主歌／副歌名稱、BPM、調性與該句歌詞。

四、GitHub Pages 自動讀取 songs 資料夾
- 一首歌放一個 JSON 到 songs 資料夾；也支援 songs 內的子資料夾。
- 使用 username.github.io 網址開啟時，網頁會在啟動時透過 GitHub API 自動列出並載入所有 JSON。
- 網頁啟動時先載入歌曲資料，但不會預先產生固定題目；每次按「換一題」才從記憶體中的歌曲與句子即時隨機抽題。
- GitHub 上新增或修改 JSON 後，重新整理網頁即可重新掃描；同一次開啟期間不會每題重抓整個資料夾。
- 不必為每首新歌修改 catalog.json；重新整理網頁後，新檔案就會加入 Level 3 抽題。
- 檔名以底線「_」開頭的 JSON 與 catalog.json 會被略過，適合放純範例。
- GitHub API 暫時無法使用、使用自訂網域或其他靜態空間時，網頁會自動改讀 songs/catalog.json。
- 下載包不再內建任何 Level 3 歌曲；底線開頭的 JSON 只是格式範例，不會成為題目。
- Level 3 使用洗牌抽歌：每首歌都抽過一次後才會重新洗牌，同一首不會連續出現。

catalog.json 備援格式：

例如：
{
  "files": ["我的歌曲.json"]
}

五、直接雙擊 HTML 與從裝置匯入
- 瀏覽器基於安全限制，不允許網頁在未詢問你的情況下列出電腦旁邊的整個資料夾；這是瀏覽器限制，JavaScript 無法繞過。
- 直接雙擊 index.html 時，請按「匯入歌曲 JSON（可多選）」一次選取所有歌曲檔案。
- 本機 `file://` 無法自動讀取 catalog.json 是瀏覽器安全限制，不代表匯入的歌曲格式錯誤；程式會將來源讀取提醒與 JSON 格式錯誤分開處理。
- Windows、Android、iPhone 都使用系統檔案選擇器，可選一個或多個 JSON。
- 匯入內容只保存在目前瀏覽器，不會上傳到伺服器。
- 同一 id 的匯入歌曲會覆蓋 catalog 版本。
- 按「清除匯入資料」可清除目前瀏覽器保存的歌曲。

六、完整歌曲格式
請直接複製 songs/_完整歌曲格式範例.json，另存為不以底線開頭的新檔名。

目前格式版本為 formatVersion: 1。舊檔案若沒有選填欄位仍可正常使用；程式也會忽略不認識的額外欄位，因此日後新增篩選條件時，不必重做既有歌曲檔案。更完整的欄位表與擴充原則請見 songs/歌曲JSON格式說明.md。

歌曲層級：
- id：歌曲唯一識別字，不要與其他歌曲重複。
- title、artist：歌名與歌手。
- bpm：全曲預設 BPM，30～240。
- key：調性文字，例如 C major、Eb major。
- source：合法樂譜或資料來源，可留空。
- language、genre、year、tags、metadata：選填的語言、曲風、年份、標籤與自訂資料。
- vocalGender：選填，使用 male、female、duet、group，供男聲、女聲、男女合唱與團體篩選。
- sections：歌曲區段陣列。

section 層級：
- id：區段識別字。
- type：verse（主歌）、chorus（副歌）、bridge（橋段）或其他文字。
- name：畫面顯示名稱，例如「主歌 1」「副歌」。
- lines：此區段內可抽題的句子陣列。

line 層級：
- id：句子識別字。
- lyric：整句歌詞。
- bpm：選填；若該句速度不同，可覆蓋歌曲 BPM。
- notes：該句逐音資料。
- tags、metadata：選填，可替個別句子標示難度、唱法或其他自訂資訊。

note 層級：
- pitch：C4、F#4、Bb3 等科學音高，或使用 midi 數字。
- beats：拍數；1 = 一拍、0.5 = 半拍、0.25 = 四分之一拍、2 = 兩拍。
- lyric：此音符對應的字。一字多音時，第一個音填字，後續音可填空字串。
- 休止符：{ "rest": true, "beats": 0.5, "lyric": "" }

七、只上傳一句
舊的單句格式仍然支援。請複製 songs/_單句格式範例.json：
- 不需要 sections。
- 直接使用 phrase 與 notes。
- 從網頁匯入時，檔名是否以底線開頭都沒有影響。
- catalog.json 不要加入純範例檔，除非真的希望它成為題目。

八、Level 1、2 音域
- 可在網頁上選擇最低音與最高音。
- Level 1 只會從範圍內抽單音。
- Level 2 只抽整段 Do Re Mi Fa Sol Fa Mi Re Do 都位於範圍內的音階。
- 音域設定會保存在目前瀏覽器。

九、鋼琴音色
- 網頁會從 Salamander Grand Piano 公開取樣網址載入鋼琴音色。
- 第一次播放需要網路；載入失敗時會改用內建合成音。

十、播放與錄音流程
- 示範開始前與錄音開始前都會在時間軸保留約 1 秒空白，游標會先走完「準備 1 秒」區域再進入第一個音符。
- 按「換一題」會抽出新題目並自動播放一次示範；「只聽示範」只負責播放，不會接著啟動錄音。
- 按「開始錄音」會直接進入 1 秒錄音準備，不會再播放一次示範。
- 按下錄音後，麥克風、橘色音高軌跡與暫存聲音會立即開始，前置 1 秒也包含在錄音與軌跡中。
- 錄音完成後可按「重播我的聲音」比較示範；播放頭、目標音條與上次錄音軌跡會依時間同步重跑。錄音只存在瀏覽器記憶體，換題或重錄即清除。
- 音高目標條固定在畫面上，只有播放進度顏色、游標與錄音音高軌跡向右前進。
- 錄音結束後會保留橘色音高軌跡供檢查；只聽示範不會清除，只有重新錄音或換題才會清除。
- 播放、錄音準備或錄音途中可直接按「只聽示範」或「換一題」；舊流程會先被完整取消，不會卡在「結束本題」。

音高偵測穩定化：
- 錄音聲音維持原始麥克風訊號；高通與低通濾波只作用在音高分析，不會改變重播音色。
- 使用 YIN 音高偵測取代單純最大自相關，降低泛音造成的八度誤判。
- 前置 1 秒會同步估計環境底噪，動態調整收音門檻。
- 以中位數與自適應平滑抑制抖動；短於約 150 ms 的掉音會延續上一個可靠音高，使軌跡不因換氣、子音或手機收音波動而頻繁斷線。
- 補上的短暫軌跡只供畫面連續顯示，不會重複計入音準分數。

十一、每日目標
- Level 1：30 關；Level 2：20 關；Level 3：10 關。
- 三個 Level 分開累計，單題音準達 70% 才算完成一關，同一題重唱不會重複計數。
- 進度保存在瀏覽器，依裝置當地日期每天自動歸零；達標時會顯示「本日目標達成」。

十二、版權
- JSON、樂譜與歌詞由你自行放入或匯入，網頁不會主動搜尋、上傳或散布歌曲資料。
- 請使用自行創作、取得授權、合法購買或符合所在地合理使用規範的內容。
